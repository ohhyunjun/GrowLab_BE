# 성장 추이 박스 추적 변경 · 2026-10-28

광각 카메라에서 대상 식물의 박스 중심이 고정된 중앙 영역 밖으로 나가면 전체 식물 박스가 빠지고 잎 일부만 측정되는 문제를 수정했다.

## 선택 방식

- 같은 재배 ID의 사진을 실제 촬영 시각 순으로 재생한다. 다른 포트·종료된 재배·새로 등록한 식물 사이에 추적 상태를 공유하지 않는다.
- 첫 유효 관측에서만 중앙 대상의 검출을 시작점으로 사용한다. 서로 겹친 잎·전체 박스를 연결한 전체 범위를 만든다. 연결된 박스의 중심이 중앙 영역 밖이라는 이유로 제외하지 않는다.
- 이후에는 이전 전체 범위와의 겹침 및 중심 거리를 함께 비교한다. 가로·세로 각각 화면의 25%까지 중심 이동을 허용한다. 800×600 이미지에서는 가로 200픽셀·세로 150픽셀이다. 식물 크기의 25%나 실제 길이가 아니며, 박스를 그 경계에서 자르는 규칙도 아니다.
- 25%는 초기 운영 설정이며 최적값이나 인식 정확도를 입증한 수치가 아니다. 먼 위치의 단일 검출은 채택하지 않고 같은 새 위치가 두 유효 관측에서 반복되면 추적을 다시 연결한다.
- 같은 식물을 추적하는 허용 거리와, 같은 촬영 조건에서 성장률을 계산하는 기준은 다르다. 기존 15% 촬영 위치 변화 판정은 성장률 계산에 유지한다. 그래프 선은 촬영 위치가 달라져도 이어서 표시하며 값을 평탄화하거나 감소 자체를 지우지 않는다.

## 과거 사진과 녹색 면적

기존 `photo` 및 재배·수확 예측 행은 삭제하거나 다른 식물에 재할당하지 않는다. 그래프 조회 시 기존 검출 JSON을 새 규칙으로 다시 연결한다.

`green_area_region`은 녹색 면적을 계산한 사각형과 규칙을 기록하는 nullable 문자열이다. 새 범위와 일치하지 않는 과거 녹색 면적은 재사용하지 않는다. 규칙이 기록되지 않은 과거 행은 이전 알고리즘이 사용한 범위를 복원해 같을 때만 사용한다.

녹색 자료가 일부 날짜에 빠지면 날짜를 지우거나 다른 지표를 이어 붙이지 않고 전체 이력을 박스 지표 하나로 표시한다. 녹색 면적이 같은 날짜 범위를 갖추면 통합 지표를 사용한다.

과거 녹색 면적을 복구하려면 `growth.green-backfill=true`를 한 번만 켠다. `growth.green-backfill-limit`은 새로 계산할 사진의 상한이다. 기존 값도 범위가 다르거나 버전이 없으면 원본 사진에서 다시 측정한다. 완료 후 설정을 해제한다. 조회 요청마다 S3 사진을 내려받지는 않는다. 원본 파일을 읽지 못한 행은 원본 값을 보존하고, 호환되지 않는 값은 그래프에서 사용하지 않는다.

## 배포

1. 스키마 자동 갱신이 꺼진 환경에서는 `database/migrations/20261028_photo_tracking_region.sql`을 먼저 적용한다. 기존 행은 보존하고 nullable 컬럼 하나만 추가하며 재실행할 수 있다.
2. BE와 FE를 함께 반영한다. 일자별 점의 기존 응답 형식을 유지하고, FE는 촬영 위치 변화에도 그래프 선을 연결한다.
3. 원하면 과거 녹색 면적을 일회성으로 재계산한다. 재계산 전에도 호환되지 않는 잎 일부 측정값을 버리고 전체 박스 이력으로 조회할 수 있다.

이 작업 자체로 운영 AWS·RPi가 교체되는 것은 아니다. AWS는 S3 및 센서 폴링을, project는 로컬 사진 저장·SSE·개발 미리보기를 유지한다. 수확일 모델의 입력 및 계수는 변경하지 않는다.
